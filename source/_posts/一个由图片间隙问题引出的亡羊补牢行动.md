# 前言

如上图所述，一个朋友上次问了我一个这样的问题，看到他发的截图，我想也没想，给父容器加个`font-size: 0`不就行了，不就是换行符导致的图片之间出现了间隙吗，要么直接不换行，像

```html
<img src=""><img src=""><img src=""><img src="">
```

要么直接设置字体大小为0，让换行符形成的文本节点直接隐藏。

<!-- more -->

这个解决的方法很早就不知道在哪篇大佬的博客里学习过了，但是学习应该是先知其然，后知其所以然，所以就有了下面的**亡羊补牢**。

# 行内元素换行导致的空白间隙

为什么说行内元素而不是说`img`标签是因为上面说的这个问题只要是行内元素都会出现，而不是只有`img`标签才会有的。下面举例依然是用`img`标签来举例，因为图片可以很容易看出来它们之间的空白间隙。

## 问题出现的根本原因

首先我们先还原出问题发生的场景：

```html
<!DOCTYPE html>
<html>
<head>
  <title>test</title>
  <style type="text/css">
  html, body {
    padding: 0;
    margin: 0;
  }
</style>
</head>
<body>
  <div>
    <img src="https://cn.bing.com//az/hprichbg/rb/GBBC_ZH-CN4481989355_1920x1080.jpg" width="400">
    <img src="https://cn.bing.com//az/hprichbg/rb/GBBC_ZH-CN4481989355_1920x1080.jpg" width="400">
    <img src="https://cn.bing.com//az/hprichbg/rb/GBBC_ZH-CN4481989355_1920x1080.jpg" width="400">
  </div>
</body>
</html>
```

打开浏览器，很好，图片之间出现了我们想要的空白间隙。

![](http://static.qvjunping.me/20190217143440.png)

上面说过问题出现的原因是因为图片间夹杂了一个换行符形成的文本节点，但是在上面的图片下面好像并没有看到除`img`标签外的其它元素了哦，那怎么办呢？

不管它在实际`render tree`中有没有，盘它！

这里有一个小技巧，当你在**chrome**开发者工具中选中某一个**dom**节点，之后在控制台你就可以用`$0`来引用这个节点了。所以我们选中`img`元素的父容器，然后在控制台打印它的所有子节点集合。这里就不详细解释`childNodes`和`children`的区别了。。。其实很简单，一个返回的集合是**NodeList**对象并且包含文本节点，另一个返回**HTML Collection**对象并且只返回元素节点。

![](http://static.qvjunping.me/20190217145025.png)

至于为什么集合的开始和结尾分别都是一个文本节点，那是因为父容器`div`的开头和结尾也都存在换行。那这些个文本节点究竟是不是换行符呢？点开它们的属性你就知道了。

![](http://static.qvjunping.me/20190217145503.png)

可能你还想说那为什么会有空白？你可以在每个`img`标签后面加个字符看看，显示为空白是因为换行符被当成空格来渲染了。或者你可以试试在控制台输入`$0.childNodes[2].remove()`看看空白是不是没了（记得先选中父容器）。

![](http://static.qvjunping.me/20190217150424.png)

## 解决办法

既然知道了问题所在，那么解决方法的要点就是隐藏或者删除掉这个由换行符生成的文本节点。

隐藏一个节点，我们可以想到很多方法，像：

- `display: none`
- `visibility: hidden`
- `opacity: 0`
- `    transform: scale(0)`
- ...

等等等，反正很多方式，但是文本节点不像元素节点，没办法直接给它设置**css**属性，所以我们只能间接地给它设置，怎么间接呢，通过**css**属性继承呗，文本的字体属性可以直接隐藏的方式，很容易就想到了字体大小，所以给父容器设置字体大小为0就是一种方法了。（但是如果父容器下面的子元素或者孙元素有包含文本的记得给它们设置字体大小）

删除一个节点，虽然可以用**JavaScript**来做到，但是能不用它来解决样式问题就尽量不用它。所以最直接的办法就是在源代码里删除掉换行，就像这样：

```html
<img src=""><img src=""><img src=""><img src="">
```

但是，就在我以为我解决了图片之间的空白间隙的时候，我却又发现了一个问题：

# 图片下方的空白间隙

咦，刚解决了横向的空白，又来了个纵向的空白，真是头大。那就继续看看它到底是个什么问题导致的。

## 问题出现的根本原因

首先猜测是不是又是什么字符隐藏在里面导致的？然后删除掉所有文本节点，只留下3个`img`节点，发现空白依旧存在！

![](http://static.qvjunping.me/20190217154154.png)

那就是图片自己本身的原因了，排除掉`padding`和`margin`，因为是行内元素，那么能影响表现得原因或者说属性就只可能是对齐方式了。

行内元素对齐方式是由`vertical-align`决定的。而`vertical-align`默认的值是`baseline`也叫做基线，什么是基线？引用一张图片来说明那就是：

![](http://static.qvjunping.me/20190217162704.png)

这里贴一下**inline-block**元素的**baseline**确定规则：

- 规则1：inline-block元素，如果内部有line box，则inline-block元素的baseline就是最后一个作为内容存在的元素inline box的baseline，而这个元素的baseline的确定就要根据它自身来定了。
- 规则2：inline-block元素，如果其内部没有line box或它的overflow属性不是visible，那么baseline将是这个inline-block元素的底margin边界。

那么我们对应一下我们的场景，`img`标签属于**inline-block**元素，内部没有**line box**，也没有设置`overflow: visible`，所以其**baseline**是底部**margin**边界，所以自然而然相对于基线对齐就会导致出现一段空白，这段空白就是字母**x**的基线和其对应的**line box**的底部的间距了。

## 解决办法

所以如果要从`vertical-align`着手，我们可以设置`vertical-align: top|middle|bottom`

![](http://static.qvjunping.me/20190217170659.png)

如果从行高出发，只要使得行高足够小或者为0，使得基线上移同样可以消除下方的空白。啥意思呢，看图：

![](http://static.qvjunping.me/20190217174809.jpg)

当设置行高为0时，基线和文字对应的**line box**的底部就会由于没有高度的支撑而上升到1的上面，并且间距为0，所以下面的空白就被消除了。

```css
div { line-height: 0; }
```

# 最后

以上问题你会发现其实用一个`font-size: 0`就可以全部解决了。。。

或者直接将其变成非行内元素就可以了，因为问题出现的原因不就是行内元素才有的么，比如直接设置`img { display: block; }`，或者给`img`元素加个`float: left`，形成一个BFC，不过记得清除浮动哦。
