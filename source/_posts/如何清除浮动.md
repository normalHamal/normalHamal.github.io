元素浮动会脱离文档流，所以当一个容器内有元素被设置浮动之后，该容器就可能会由于没有子元素高度的支撑而出现塌陷的情况。所以我们一般地需要对设置浮动元素的父容器进行浮动清除。

## 固定高度

当然你也可以直接给父容器一个固定高度，但是对于未知高度的容器就不友好，因为最终容器内的元素还是有可能超出你设置的高度造成塌陷、或者远远低于你设置的高度造成大量未被使用的空间以及空白。

## BFC

**块格式化上下文（Block Formatting Context，BFC）** 是Web页面的可视化CSS渲染的一部分，是块盒子的布局过程发生的区域，也是浮动元素与其他元素交互的区域。- [MDN](https://developer.mozilla.org/zh-CN/docs/Web/Guide/CSS/Block_formatting_context)

为什么说**BFC**可以清除浮动，这里请看[W3C](https://www.w3.org/TR/CSS2/visuren.html#block-formatting)上给出的一句话：

> In a block formatting context, each box's left outer edge touches the left edge of the containing block (for right-to-left formatting, right edges touch). This is true even in the presence of floats (although a box's *line boxes* may shrink due to the floats), unless the box establishes a new block formatting context (in which case the box itself [*may* become narrower](https://www.w3.org/TR/CSS2/visuren.html#bfc-next-to-float) due to the floats).

也就是说，在一个**BFC**内，即使是浮动元素也会被容器包含并计算宽高，所以父容器高度塌陷的问题就得以解决了。

但是，利用**BFC**来清除浮动必定会在父容器上**多加一些原本可能不需要的css属性**，导致可能出现为了清除浮动而出现原本不应该出现的滚动条这种情况等等，形成**BFC**的属性比如

- overflow: hidden
- float: left
- position: absolute
- ...

具体可参考[MDN-BFC](https://developer.mozilla.org/zh-CN/docs/Web/Guide/CSS/Block_formatting_context)

## clear

用了这么久的clear，一直以来都只知道它可以用来清除浮动，但是却从来没有去了解过这个属性的具体作用，真是惭愧。

### clear的作用

> clear属性只对块级元素才有效

先来看一个[MDN](https://developer.mozilla.org/zh-CN/docs/Web/CSS/clear)上给出的关于clear属性的一个[demo](https://interactive-examples.mdn.mozilla.net/pages/css/clear.html)

{% iframe https://interactive-examples.mdn.mozilla.net/pages/css/clear.html %}

也就是说，**clear**属性其实就是指定元素是否必须移动到**它之前的浮动元素**下面，注意！是移动到它之前的浮动元素下面。并且！这个属性对于浮动和非浮动元素都适用。那么很显然，当你移动到浮动元素的下面而不是环绕它时其实间接就已经清除掉了浮动元素给你带来的作用了。

![](https://cdn.normalhamal.online/20190319192344.png)

上面这张图片中，我将**Left**所在的块元素设置了`clear: both`，但是我们可以从图片的结果中看出并没有什么变化，然后我再将**Right**所在的块元素设置`clear: both`，得到了下面的输出结果：

![](https://cdn.normalhamal.online/20190319192800.png)

那么我们就很容易可以肯定了上面的定义：“clear属性只能指定元素是否移动到它之前的浮动元素下面”，因为我们给**Left**设置**clear**属性发现没有变化，而给**Right**设置**clear**属性发现**Right**移动到了**Left**下面，因为**Right**由于设置了**clear**而移动到了它之前的浮动元素Left下面。

同时也证明了**clear**属性对于浮动元素同样起作用。

### clear清除浮动的方式

**增加额外的元素**

既然知道了clear的作用，那么对于如何清除浮动元素带来的父容器高度塌陷问题，我们很容易就可以想到在父容器的最后加一个空元素，再给它设置一下`clear: both`，就可以很轻松就解决了清除浮动的问题。

```html
<div class="box">
    <div class="float">I am a floated box!</div>
    <p>I am content inside the container.</p>
    <div class="clearfix"></div>
</div>
```

```css
.float { float: left }
.clearfix { clear: both }
```

这种做法的弊端就是莫名多加了一个空标签，如果有多个地方需要清除浮动的话，你就得每个地方都加上一个这样的标签，造成文档体积增大。

**利用伪元素**

直接上代码了

```html
<div class="box">
    <div class="float">I am a floated box!</div>
    <p>I am content inside the container.</p>
</div>
```

```css
.float { float: left }
.box::after {
    content: '';
    display: block | table;
    clear: both
}
```

因为clear属性只对块级元素才有效，所以我们需要将伪元素设置为块级元素。也就是需要设置`display: block | table;`

当然，伪元素在早期的IE版本（6-7）中其实是不支持的，所以如果你还需要兼容它们的话，你可以使用**IE hacks**(触发hasLayout)来兼容：

```css
.box { zoom: 1 }
```

## display: flow-root

先上一张关于各大浏览器的支持性的图：

![](https://cdn.normalhamal.online/20190319203216.png)

然后再来讲讲这个属性和值有什么用，简单地来说，就是设置了这个属性值的元素会生成一个块级盒子，并且盒子里的内容使用的是流式布局，它总是会为它建立一个新的块格式化上下文内容。

> The element generates a block container box, and lays out its contents using flow layout. It always establishes a new block formatting context for its contents. - [W3C](https://drafts.csswg.org/css-display/#valdef-display-flow-root)

听起来，和创建**BFC**不是一样的吗。。。

那么既然支持性不好，那就得兼容处理了，这里我们可以使用`@supports()`完美降级处理：

```html
<div class="box">
    <div class="float">I am a floated box!</div>
    <p>I am content inside the container.</p>
</div>
```

```css
.float { float: left }
.box { display: flow-root }
@supports not (display:flow-root) { 
    .box::after { 
        content: ''; 
        display: block; 
        clear:both; 
    } 
}
```

## 最后

总的来说，在网页上布局时，想要清除浮动最好还是使用伪元素来清除，兼容性比较好处理并且文档结构会比较清晰。当然具体问题具体分析，如果你父容器也需要将溢出内容隐藏的情况下，使用`overflow: hidden`触发**BFC**的方式来清除浮动岂不是一举两得。
