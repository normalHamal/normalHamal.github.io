### 前言

最近在做本科毕业设计，估计是个**瞧不上眼**的作品~，中间有个需要用到瀑布流布局的页面，估计后面还会针对这个页面加一些比如无限滚动加载、超前阈值的懒加载等等。

<!-- more -->

![](http://static.qvjunping.me/20190114163208.png)

> 瀑布流，又称瀑布流式布局。是比较流行的一种网站页面布局，视觉表现为参差不齐的多栏布局，随着页面滚动条向下滚动，这种布局还会**不断加载数据块**并附加至当前尾部。最早采用此布局的网站是[Pinterest](https://www.pinterest.com/)，逐渐在国内流行开来。

话不多说，往下探寻 ↓↓↓

### css解决方案

#### Flex布局

既然是一种布局解决方案，我们很快就想到了Flex布局~

虽然Flex布局还存在兼容问题，比如旧版本语法`display: box`，过渡版本`display: flex box`，然后就是现在的标准版本`display: flex`，所以如果你只是写新版本的语法形式，是肯定存在兼容性问题的。

兼容性可以看下面这张图，主要是在移动端支持不太好，其次是IE：

![](http://static.qvjunping.me/20190114191335.png)

下面是Flex的两列瀑布流布局实现：

![](http://static.qvjunping.me/553eb674-5097-45ae-9e13-d9c9950cbfae.gif)

{% jsfiddle normalHamal/qk0jc1p4/2 result,html,css light %}

主要实现原理就是在一行里面放置两列，这两列通过设置Flex的主轴方向为垂直方向，起点为上沿，从而实现瀑布流两列布局。

要注意的是这两列必须显示固定宽度，你可以按照设计稿中的的样式来设定，也可以使用**calc()**方法来设置`width: calc(100% / 2)`

主体布局如下：

```css
.row {
  display: -webkit-flex;
  display: flex;
  justify-content: space-between;
}

.waterfall {
  display: -webkit-flex;
  display: flex;
  flex-flow: column wrap;
}
```



```html
<div class="row">
    <div class="waterfall">
        <div class="waterfall_item">...</div>
        <div class="waterfall_item">...</div>
        ...
    </div>
    <div class="waterfall">
        <div class="waterfall_item">...</div>
        <div class="waterfall_item">...</div>
        ...
    </div>
</div>
```

当然，你也可以采用另一种Flex实现的瀑布流布局，这种实现方式的一个缺陷就是你需要**显示地**设置最外层容器的高度，特别对于响应式设计来说这个更为不友好，当然好处就是可以自适应多列布局。

```css
.waterfall {
  display: -webkit-flex;
  display: flex;
  flex-flow: column wrap;
  height: 1600px;
}
```



```html
<div class="waterfall">
    <div class="waterfall_item">...</div>
    <div class="waterfall_item">...</div>
    ...
</div>
```

因为这种方案对于我们之后还要进行动态地加载插入数据不太友好，因为要每增加一条数据，我们就要对整个waterfall的高度进行一次计算和赋值，所以就不贴具体实现代码了~

#### column-count属性需要注意的地方

**break-inside: avoid**

这个属性是为了控制文本块分解成单独的列，以免项目列表的内容跨列，破坏整体的布局。

不理解没关系，看看这篇文章就很好懂了[break-inside](https://tympanus.net/codrops/css_reference/break-inside/)

虽然使用column-count属性的布局不会出现像Flex布局一样的过长空白区域，但是需要注意到使用column-count分列的布局，列表元素的排列顺序并不是正常的从左到右（也就是**Z**字型排列），而是呈现出一种**N**字型排列。
