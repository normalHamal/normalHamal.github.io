ASCII码

很久很久以前，当全世界只有美国人开始在用电脑的时候，他们一开始只是用它来进行不同状态的组合和计算，比如晶体管的开合对应1和0，然后用这两个数字进行组合和计算。

后来他们又想把除了表示状态信息的0和1以外再存储和显示一些字符，比如26个基本的拉丁字母、阿拉伯数字和一些标点符号等等，于是在1967年的时候他们发表了ASCII（American Standard Code for Information Interchange，美国信息交换标准代码），再在后来不断地进行补充一直到定义了128个字符。

对于如何让计算机识别并存储你所输入的字符，美国人是这么干的：用一个字节也就是8个bit来存储上面所说的字符，那么一个字节总共可以组合的状态就是2的8次方也就是256种，但是他们只用到了前面的128种状态。具体的做法就是用8个可以开合的晶体管来表示一个字节，比如：

具体可以去这里查看更为详细的对于控制字符的解释和说明。

ASCII码的扩展EASCII

ASCII的局限在于只能显示26个基本拉丁字母、阿拉伯数目字和英式标点符号，因此只能用于显示现代美国英语。

于是，等到全世界都开始用上计算机的时候，各个国家也想要在计算机里面保存他们的文字，于是他们只能把目光放在了那空出来的128个位置（上面说过ASCII码只用到了1个字节可以保存的最大组合状态的一半）。

于是就出现了下面这些用来扩充ASCII码的字符编码，主要包括表格符号、计算符号、希腊字母和特殊的拉丁符号。

ISO/IEC 8859-*

ISO-8859-1编码是单字节编码，向下兼容ASCII，其编码范围是0x00-0xFF，0x00-0x7F之间完全和ASCII一致，0x80-0x9F之间是控制字符，0xA0-0xFF之间是文字符号，别名Latin-1。

此编码支持部分于欧洲使用的语言，除此之外，欧洲以外的部分语言也可以使用，具体可参考百度百科。

那么它具体加入了哪些字符呢？你可以使用如下方法打印一遍从128到255就知道了。

  • 在Windows下，打开小键盘，按住ALT键，然后输入EASCII码［如按住ALT键并依次输入数字键区数字1、6、9可输入带著作权符的©］。
  • 在Vim中，在插入模式下，可以先按Ctrl-V，再输入代表EASCII码的（至多三位）[十进制]数字。

法语及芬兰语本来也使用ISO/IEC 8859-1来表示。但因它没有法语使用的 œ、Œ、Ÿ 三个字母及芬兰语使用的 Š、š、Ž、ž ，故于1998年被ISO/IEC 8859-15所取代，简称Latin-9俗称Latin-0。

还有很多比如ISO-8859-6（阿拉伯文）、ISO-8859-14（塞尔特文）等等统称ISO/IEC 8859，是国际标准化组织（ISO）及国际电工委员会（IEC）联合制定的一系列8位字符集的标准，现在定义了15个字符集了，也就是从ISO-8859-1一直到了ISO-8859-15。

Code Page 437（CP 437）

这也是一种对ASCII码的扩展字符编码，是始祖IBM PC或者MS-DOS使用的，这个字符集的出现只是当时的IBM PC用来图像化的表现字形而已。比如这样的图像字符：☺、♥等等，它也向下兼容ASCII。

ANSI

ANSI是一种字符代码，为使计算机支持更多语言，通常使用 0x00~0x7f 范围的1 个字节来表示 1 个英文字符。超出此范围的使用2个字节0x80~0xFFFF来编码，即扩展的ASCII编码。

比如在简体中文Windows操作系统中，ANSI 编码代表 GBK 编码；在繁体中文Windows操作系统中，ANSI编码代表Big5；在日文Windows操作系统中，ANSI 编码代表 Shift_JIS 编码。如果你想自己更改ANSI编码方式，你可以通过在控制面板中更改区域选项设置来更换缺省代码页（下面有说明）：

GB2312、GBK、GB18030、BIG5

上面所说国家或者地区所使用的语言文字都可以被一个字节所包含，可是这对于我们古老的汉字来说，256是远远不够的，目前来看常用的汉字的数量估计已经超过6000个了，这还没包括那些深远偏僻的字，所以为使计算机支持更多语言，通常使用 0x80~0xFFFF 范围的 2 个字节来表示 1 个字符。

这个时候伟大而又充满智慧的中国人民开始发力，创造出一套包含数学符号、罗马希腊的字母、日文的假名以及中国的汉字的字符编码，连在 ASCII 里本来就有的数字、标点、字母都统统重新编了两个字节长的编码。它就是GB2312，它规定了两个连续大于 127 的字节代表一个汉字， 否则就当做 ASCII 来处理， 这样的两字节中高位字节范围 0xA1-0xF7（161-247）， 低位字节范围 0xA1-0xFE（161-254），两者相乘就有了7998个位置可以用来表示非ASCII码了。

后来扩展了一些新的符号和繁体字之后（因为GB2312只收录了6763个汉字），就把GB2312扩成了个GBK标准（中间好像牵扯到某个国家领导人。。。）。GBK 放开了一些范围， 相比 GB2312 ， GBK 的高位字节扩展到了 0×81-0xFE（129-254）， 低位字节扩展到了 0x40-0xFE （64-254）(不包含0x7F（127）) 编码方式和 GB2312 相同。

后来少数民族也用上计算机了，就把他们的文字也编进来，GBK就又扩成了GB18030。GB18030 是目前我国最新的内码字集， 它和其他 GB 开头的编码集最大的区别就是，它是变长的编码集，可能是一个字节兼容ASCII，也可能是2个或者4个字节。

BIG5，又称为大五码或五大码，普及于台湾、香港与澳门等繁体中文通行区。

code page

目前Windows的内核已经支持Unicode字符集，这样在内核上可以支持全世界所有的语言文字。但是由于现有的大量程序和文档都采用了某种特定语言的编码，例如GBK，Windows不可能不支持现有的编码，而全部改用Unicode。

Windows使用代码页(code page)来适应各个国家和地区。code page可以被理解为前面提到的ANSI。GBK对应的code page是CP936。

微软也为GB18030定义了code page：CP54936。但是由于GB18030有一部分4字节编码，而Windows的代码页只支持单字节和双字节编码，所以这个code page是无法真正使用的。

Unicode和UCS

随着互联网的发展，全世界各个国家之间的人们开始通过互联网走向世界，但是刚一出来就发现，到处都是看不懂的奇奇怪怪的符号，算了打扰了。

于是人们就在想，我们能不能定义一个超大的字符集，它可以容纳全世界所有的文字字符，再对它们统一进行编码，让每一个字符都对应一个不同的编码值，从而就不会再有乱码了。

当时，世界上有2个机构早就在做这个打算了，一个是ISO/IEC组织，一个是Unicode组织（也叫统一码联盟）。前者制定了ISO/IEC 10646标准，后者发布了Unicode标准。当然最后这两个组织都发现了一个问题，那就是字符集有一个就够了，所以，他们开始合作，ISO/IEC组织提供 ISO/IEC 10646 国际编码标准内的字符及编码资料，Unicode 组织则对这些字符及编码资料提出应用的方法以及语义资料作补充。

由于提出合作后，两个组织各自维护的字符集已经互相兼容并且同步，同时Unicode因为名字比较好记，所以人们都愿意称呼这个统一的字符集为Unicode，而不是类似ISO/IEC 10646-2:2001。他们之间的对应关系大致如下：

Unicode

目前的Unicode字符分为17组编排，0x0000 至 0x10FFFF，每组称为平面（Plane），而每平面拥有65536个码位，共1114112个（17 x 65536）。然而目前只用了少数平面。

这17个平面分别由一个基本平面加16个辅助平面组成。基本平面的码点范围从U+0000到U+FFFF。辅助平面的码点范围从U+010000一直到U+10FFFF。

它同时也兼容ASCII码，0x0000 - 0x007F表示的还是原来的ASCII码，只不过把长度由一个字节转换成了2个字节长。

UTF是“Unicode Transformation Format”的缩写，可以翻译成Unicode字符集转换格式，即怎样将Unicode定义的数字转换成程序数据。

UTF-32与UCS-4

在Unicode与ISO 10646合并之前，ISO 10646标准为“通用字符集”（UCS）定义了一种31位的编码形式（即UCS-4），其编码固定占用4个字节，编码空间为0x00000000~0x7FFFFFFF（可以编码20多亿个字符）。

UCS-4有20多亿个编码空间，但实际使用范围并不超过0x10FFFF，并且为了兼容Unicode标准，ISO也承诺将不会为超出0x10FFFF的UCS-4编码赋值。由此UTF-32编码被提出来了，它的编码值与UCS-4相同，只不过其编码空间被限定在了0~0x10FFFF之间。因此也可以说：UTF-32是UCS-4的一个子集。

UTF-32与UCS-4在存储和传输时会使用两种不同的字节序，分别是big endian和little endian（大端和小端），下面再具体讲字节序的问题。

UTF-16与UCS-2

除了UCS-4，ISO 10646标准为“通用字符集”（UCS）定义了一种16位的编码形式（即UCS-2），其编码固定占用2个字节，它包含65536个编码空间（可以为全世界最常用的63K字符编码，为了兼容Unicode，0xD800-0xDFFF之间的码位未使用）。

但是2个字节明显不够，于是UTF-16诞生了，与UCS-2一样，它使用两个字节为全世界最常用的63K字符编码，不同的是，它使用4个字节对不常用的字符进行编码。UTF-16属于变长编码。

UCS-2和UTF-16在存储和传输时也会使用两种不同的字节序。

UTF-8

虽然上面已经出现了UTF-16和UTF-32，对于Unicode的编码已经可以很好的处理了，但是，那个年代，宽带和硬盘都远远比不上现在的情况下，对于UTF-32来说，存储或者传输一个英文字符需要4个字节，而对于UTF-16来说需要2个字节，但是，ASCII码只需要1个字节啊！这也太浪费资源了，更何况那个时代资源都很吃紧的情况下。

于是出现了UTF-8。UTF-8是一种变长的编码方法，字符长度从1个字节到4个字节不等。越是常用的字符，字节越短，最前面的128个字符，只使用1个字节表示，与ASCII码完全相同。具体规则如下：

  1. 对于ASCII码中的符号，使用单字节编码，其编码值与ASCII值相同。其中ASCII值的范围为0~0x7F，所有编码的二进制值中第一位为0（这个正好可以用来区分单字节编码和多字节编码）。
  2. 其它字符用多个字节来编码（假设用N个字节），多字节编码需满足：第一个字节的前N位都为1，第N+1位为0，后面N-1 个字节的前两位都为10，这N个字节中其余位全部用来存储Unicode中的码位值（将Unicode值转换为2进制，再依次从后向前填入格式中的x，多出的位补0）。

字节序

字节序有两种，分别是“大端”（Big Endian, BE）和“小端”（Little Endian, LE）。

名字由来

在乔纳森·斯威夫特的著名讽刺小说《格列夫游记》中，小人国内部分裂成Big-endian和Little-endian两派，区别在于一派要求从鸡蛋的大头把鸡蛋打破，另一派要求从鸡蛋的小头把鸡蛋打破。斯威夫特借以讽刺英国的政党之争，在计算机工业中指数据储存顺序的分歧。

如何定义

所谓的大端模式（Big-endian），是指数据的高字节，保存在内存的低地址中，而数据的低字节，保存在内存的高地址中，小端则相反。

具体应用

根据字节序的不同，UTF-16可被实现为UTF-16LE或UTF-16BE，UTF-32可被实现为UTF-32LE或UTF-32BE。例如：

Unicode编码UTF-16LEUTF-16BEUTF32-LEUTF32-BE
0x006C4949 6C6C 4949 6C 00 0000 00 6C 49
0x020C3043 D8 30 DCD8 43 DC 3030 0C 02 0000 02 0C 30

如何区分

Unicode标准建议用BOM（Byte Order Mark）来区分字节序，即在传输字节流前，先传输被作为BOM的字符“零宽无中断空格”。这个字符的编码是FEFF，而反过来的FFFE（UTF-16）和FFFE0000（UTF-32）在Unicode中都是未定义的码位，不应该出现在实际传输中。

下表是各种UTF编码的BOM：

UTF-8 with BOMEF BB BF
UTF-16LEFF FE
UTF-16BEFE FF
UTF-32LEFF FE 00 00
UTF-32BE00 00 FE FF

为啥要有大小端之分

这就好比为啥前端写代码需要兼容不同浏览器一样，不同的CPU对数据的存储方式不同，所以有的用大端、有的用小端，具体没有优缺点之分，只是没有标准，不同的厂商自己搞自己的一套而已。

我们常用的X86结构是小端模式，而KEIL C51则为大端模式。很多的ARM，DSP都为小端模式。有些ARM处理器还可以随时在程序中(在ARM Cortex 系列使用REV、REV16、REVSH指令 )进行大小端的切换。
