关于前端代码格式规范的那些事

发表于 2019-01-24 | 更新于 2021-01-18 | 分类于 前端 | 评论数： | 阅读次数：
本文字数： 6.1k | 阅读时长 ≈ 6 分钟

9102年，作为一个前端人员，或者说一个码农，你总会对自己的代码产生点洁癖。

面对如今前端的大生态，各种代码和配置文件的编写总会让你感觉到一团糟。

为什么在我的电脑上排版没问题，提交到远程仓库就各种缩进错误；为什么在我Windows电脑上显示没问题，换到同事Mac上就连最基本的字符都乱了；为什么我用sublime你用VSCode，代码格式化之后就不一样了。

代码风格，没有绝对的对错，但是对于团队开发来说，统一风格才是王道。

EditorConfig

EditorConfig在我看来就是一个配置统一的文件编码以及格式的工具。

从官方的wiki说明上我们可以看到，目前它仅仅只支持8个可配置属性，但是未来它可能支持更多。

一个有效的EditorConfig配置文件应该以.editorconfig命名并且如下设置属性：

属性描述可能的值
indent_style代码缩进的样式tab、space
indent_size缩进的大小tab、an integer
tab_width一个简单的制表符（tab）宽度a positive integer (defaults indent_size when indent_size is a number)
end_of_line换行符lf、crlf、cr
charset文件的字符编码latin1、utf-8、utf-16be、utf-16le、utf-8-bom
trim_trailing_whitespace表示行末是否允许空格true、false
insert_final_newline表示文件结尾是否插入一个空行true、false
max_line_length在达到指定字符数量之后强制换行positive integers、off

对于文件的通配符匹配规则（INI like format）如下：

通配符说明
*匹配任意字符串，除了/
**匹配任意字符串
?匹配任意字符
[name]匹配name中任意单个字符，比如a
[!name]匹配非name中任意单个字符，比如b
{s1，s2，s3}匹配任意一个给出的字符串
{num1..num2}匹配num1到num2中任意一个整数

root属性

关于这个root属性有什么用，官方网站上给出的是：

root: special property that should be specified at the top of the file outside of any sections. Set to true to stop .editorconfig files search on current file.

root: 应该被特别地放置在文件的最上面的特殊属性。如果设置为true就会停止在当前文件下搜索.editorconfig文件。（中式英语翻译）

反正不管怎么翻译，最后你会发现其实它真正的用法都是没办法从这行话中得到的。。。

最后我在微软的Visual Studio 2017操作指南上得到了答案，并且经过自己测试得出以下解释：

.editorConfig 文件设置应用于同级目录以及任何子目录中的文件

上一级目录下的.editorConfig文件默认情况下会影响并替代任何子目录中的.editorConfig文件中没有显示设置的属性。

一般地，我们会在项目根目录创建一个.eslintrc.*文件来作为配置文件，或者你可以直接在package.json文件里的eslintConfig字段指定配置。

IDE插件

Prettier

Prettier是什么？

它是一个可以完全统一你的代码风格的工具，在之前，Javascript官方一直没有一个严格的代码风格，虽然业界有一些比较流行的代码风格，比如Airbnb和Standard，但是你得学习它们的文档并投入使用，这可能会花费掉你一点点时间。

现在有了Prettier，它有着自己的规则来将你的代码重新格式化，虽然你可能会认为可配置的代码风格工具才是最好的，就像ESLint，但是，当你遵从流行的代码风格反而需要不停地fix你的ESLint Error的时候，你会发现，只需要保存文件，工具便自动帮你格式化好代码并统一风格是有多么的好了。

那么总结下它的好处，那就是以下几点：

  1. 不用修复ESLint报告的风格问题。
  2. 保存文件的时候自动统一风格。
  3. 不用学习其他人的代码风格。
  4. 不用再去争论规则的对与错。

Prettier一共有四种配置方式：

  1. 根目录创建.prettierrc文件，能够写入YML、JSON的配置格式，并且支持.yaml/.yml/.json/.js后缀.
  2. 根目录创建.prettier.config.js文件或者.prettierrc.js，并对外export一个对象.
  3. 在package.json中新建prettier属性.
  4. 根目录创建.prettierrc.toml 文件，后缀.toml是必须要的.
